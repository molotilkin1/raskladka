# Раскладка

Планировщик питания для горных походов. Замена Excel-таблицам завхоза: от раскладки по дням и приёмам пищи — до списка закупки, упаковки, распределения продуктов между участниками и полевого экрана «кто что достаёт».

## Зачем

Сейчас раскладка собирается в Excel: продукты по дням и приёмам, нормы на человека, суммарные веса, закупка, распределение по участникам. Документ состоит из нескольких связанных листов, и каждая правка — число участников, добавленный день, изменение нормы — должна вручную прокатиться по всей цепочке до веса рюкзака. Копии расчёта расходятся, названия продуктов пишутся по-разному, а итоговый список «кто что несёт» остаётся свободным текстом, который в поле приходится толковать на ходу.

«Раскладка» делает расчёт одноразовым: поход описывается один раз, а веса, список закупки, список упаковки и полевой экран строятся из него автоматически.

## Что умеет (v1)

- **Поход** — название, дата начала, дни 1..N с календарными датами, список участников.
- **Кольца** — разбиение маршрута на участки между забросками; у каждого кольца свои дни, своя матрица продуктов и свои нормы. Кольцо можно пометить как завозимое заранее (заброска), и его вес виден отдельно.
- **Продукты** — название, единица измерения (граммы или штуки), для штучных — вес одной штуки, чтобы закупка и вес похода считались в килограммах. Автодополнение по уже введённым продуктам похода.
- **Нормы** — на человека за приём, на связке «кольцо + продукт + приём»; одна норма действует на все дни кольца.
- **Раскладка** — сетка «продукты × дни» с группировкой по приёмам (завтрак, обед, ужин, КП) и числом порций в клетке; карточка приёма с названием блюда.
- **Вес** — по записи, приёму, дню, кольцу и походу; вес заброски отдельно; справочный индикатор «вес / участники / дни».
- **Закупка** — список «продукт → количество и суммарный вес», ручная правка количества (округление до реальной упаковки), копирование в буфер для чата группы.
- **Упаковка** — список пакетов «день + приём → что положить» с количествами, без отметок «упаковано».
- **Распределение** — каждый продукт приёма назначается одному участнику (в том числе массово на всё кольцо); из назначений складывается кучка участника; измеренный вес кучки вводится вручную. Вес рюкзака на человека приложение не считает (см. ADR-0002).
- **Полевой экран** — read-only, офлайн: день → приём → блюдо → продукт → кто достаёт, без граммовок и весов.
- **Данные** — хранение в браузере (IndexedDB), автосохранение, экспорт и импорт похода в JSON, работа офлайн (PWA).

## Для кого

Только завхоз — тот, кто отвечает за раскладку, закупку и распределение продуктов. Интерфейс на русском. В v1 передача данных участникам не поддерживается: участники получают распределение в виде сообщения или распечатки полевого экрана.

## Технологии

- TypeScript + React 19 + Vite
- Хранение: IndexedDB через `idb`
- Офлайн: `vite-plugin-pwa`
- Тесты: Vitest, Testing Library, `fake-indexeddb`

Архитектура: доменный модуль — чистый TypeScript без React и без доступа к хранилищу; хранилище скрыто за портом `TripStore` с IndexedDB-адаптером и in-memory фейком для тестов.

## Запуск

```bash
npm install
npm run dev          # dev-сервер
npm run build        # сборка (tsc + vite)
npm run preview      # просмотр сборки
npm test             # тесты
npm run typecheck    # проверка типов
```

## Данные и резервные копии

Данные лежат в браузере (IndexedDB). Очистка данных браузера уничтожит походы, поэтому регулярно делайте экспорт в JSON через интерфейс и храните файл вне браузера.
